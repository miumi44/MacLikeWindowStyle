# WindowBridge 0.2.0 검증 기록 — 2026-10-20

## 자동 검증

현재 수정본에서 `scripts/test-windowbridge.sh`, release 빌드·타입 검사, 앱 코드 서명 검증, `git diff --check`가 모두 통과했습니다. 변경 파일의 개인 경로·토큰/개인키 패턴 검색에서도 발견 항목이 없었습니다. 이는 전체 보안 감사나 정량적 커버리지 측정은 아닙니다.

검증 진입점은 `scripts/test-windowbridge.sh`입니다. 각 실행기는 실제 의미 있는 상태·결과를 검사하며, assertion 개수를 별도 테스트 개수로 세지 않습니다. 커버리지 비율은 측정하지 않았습니다. `Package.swift`에는 XCTest 대상이 없으므로 `swift test` 대신 이 스크립트를 사용합니다.

| 영역 | 검사 내용 |
| --- | --- |
| 창 전환 | 선택·순환·행 이동·포커스 판정·썸네일 순서/캐시·반복 세션 |
| 패널 | 백그라운드 표시 및 키 포커스 설정 |
| 키보드·마우스 설정 | 독립 켜기/끄기, 알 수 없는 설정 보존, 잘못된 JSON과 미지원 구성, 소수 휠 간격 |
| 설정 저장·복구 | 무변경 적용, 백업·충돌·복원·롤백, 기존 한영 매핑 충돌 거부, 마우스/전역값 저장·복원, 복구 실패 재시도 |
| 창 크기 | 네 방향 좌표, 화면 경계 제한, 실제 크기 비교, 타일→최대화→원래 크기 복원, 닫힌 창 상태 제거 |
| 단축키 상태 | 동작키와 수정키 해제 순서, 반복·취소, 일반 문자·입력 소스 키 구분 |
| 실제 이벤트 처리 함수 | 비발송 CGEvent 객체로 down/up 소비·통과, flagsChanged 보존, Escape 취소, 끌 때 해제 대기, 누락된 key-up 뒤 새 일반 입력 복구 |

설정 테스트는 임시 디렉터리와 가짜 명령 실행기를 사용합니다. 이벤트 테스트는 `HotKey.receive`를 직접 호출하며 event tap을 설치하거나 키 입력을 운영체제에 보내지 않습니다. 따라서 물리 키보드 검증을 대신하지 않습니다.

빌드·타입 검사는 `scripts/build-windowbridge.sh`의 Swift release 빌드와 `codesign --verify --deep --strict`로 수행합니다. 별도 Swift lint 도구는 설정되어 있지 않으며 `git diff --check`로 공백 오류를 검사합니다. 토큰·개인 경로 등 공개에 부적합한 내용도 변경 파일에서 별도 확인합니다.

## 재현한 문제와 수정

- 최초 창 배치 버전에서 한영 전환 불가·자모 분리 입력이 보고됐습니다. 앱 종료 후 입력이 정상화됐고, 기존 Alt+Tab만 켠 상태에서도 정상이라는 사용자 확인이 있었습니다. 종료와 수정키 재입력이 함께 이뤄져 직접 원인은 확정되지 않았습니다.
- 소비한 방향키 down에 대응하는 up도 함께 처리하고, 동작키 및 Command·Option을 모두 놓은 뒤 동작하도록 보강했습니다. 일반 문자·Caps Lock·오른쪽 Option은 이 새 기능이 소비하지 않습니다.
- 기능을 끌 때 이미 소비한 down의 up까지 처리한 다음 event tap을 해제합니다. 중단 중 up을 놓쳐도 새 nonrepeat down은 오래된 상태를 정리하고 정상적으로 처리합니다. 이 누락 경로는 회귀 테스트에서 실패를 먼저 재현했습니다.
- AX 쓰기 성공만으로 창 배치 성공을 판단하던 방식을 바꿨습니다. 실제 프레임을 재조회하고 제한된 재시도를 수행하며, 창 크기가 제한되거나 동작이 일부만 적용되면 성공과 구분해 안내합니다.
- 단축키 시작 시 캡처한 앱·창이 달라지면 취소합니다. 절전 시 실행 중인 작업도 취소하고, 실패한 최대화를 완료 상태로 기록하지 않도록 검토했습니다.

## 실제 기기 검증

아래 항목은 자동 테스트와 분리해 확인해야 합니다. 확인하지 않은 항목을 통과로 간주하지 않습니다.

- 메뉴에서 작은 일반 창을 네 방향으로 배치하고 실제 크기 확인
- 최대화 → 복원, 타일 → 최대화 → 복원, 현재 창 최소화
- 다른 앱/창으로 전환했을 때 잘못된 창을 변경하지 않는지 확인
- `Alt+Tab만 → 새 단축키 켜고 미사용 → 새 단축키 사용 → Alt+Tab 재사용` 단계별 한영 전환과 실제 한글 조합
- 키 해제 순서, 빠른 연타, Esc 취소, 설정 창을 닫은 상태
- 앱별 최소 크기·고정 크기·전체 화면, 보조 화면 배치 및 Spaces

새 버전 설치와 기존 권한 재연결 후, 설정 UI의 새 옵션 표시 및 실제 창 썸네일·행 이동·선택한 Safari 창으로의 실제 포커스 전환을 확인했습니다. 사용자 물리 키보드 테스트에서 왼쪽 절반 배치의 창 크기 조정, 최대화·복원, Alt+Tab 이후 오른쪽 한영키 전환과 한글 조합이 모두 정상이라는 확인을 받았습니다. 추가 물리 키보드 테스트에서 현재 창 최소화 → Alt+Tab 복귀 → 오른쪽 한영키 및 한글 조합도 모두 정상이라는 사용자 확인을 받았습니다. 앱·키보드·보조 화면의 모든 조합을 검증한 것은 아니므로 창 관리 단축키는 기본 꺼짐인 실험 기능으로 유지합니다. 기존 입력 설정 파일을 덮어쓰지 않습니다.

## 이번 구현 범위

네 방향 절반 배치를 유지하고 화면 채우기 최대화/복원, 현재 창 최소화, 배치 전 크기 복원 메뉴를 추가했습니다. 바탕화면 일괄 표시, 가상 데스크톱 제어, 사분면/Snap 그룹, 클립보드 기록은 이번 구현에 포함하지 않았습니다.
